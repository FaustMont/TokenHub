# Адаптер источника LiteLLM

## Поддерживаемые версии

`>=1.52.0, <1.70.0`

## Входные данные

Адаптер считывает файл `proxy_config.yaml` LiteLLM. Будущие версии также будут поддерживать дампы базы данных Postgres.

## Сопоставление возможностей

| Возможность LiteLLM | Эквивалент TokenHub | Статус |
|---------------------|---------------------|--------|
| Провайдеры `model_list` | Провайдеры + Ресурсы провайдеров | Поддерживается |
| Модели `model_list` | Модели | Поддерживается |
| Маршрутизация `model_list` | Маршруты | Поддерживается |
| `key_management_settings.teams` | Команды (метаданные) | Поддерживается |
| `key_management_settings.users` | Пользователи-администраторы | Поддерживается |
| `key_management_settings.virtual_keys` | API-ключи | Поддерживается |
| `key_management_settings.budgets` | — | Только предупреждение |
| `general_settings` | — | Частично, предупреждение |
| `router_settings` | — | Частично, предупреждение |
| `environment_variables` | SecretRef | Поддерживается |

## Неподдерживаемые возможности

Следующие возможности LiteLLM пока не сопоставлены и будут отображаться в виде предупреждений:
- Бюджеты и лимиты расходов
- Callback-вызовы (успех/сбой)
- Guardrails (ограничения безопасности)
- Цепочки fallback-переключения
- Сквозные маршруты (pass-through)
- Не-OpenAI-совместимые провайдеры
- Эндпоинты аудио и изображений
- Кэширование промптов

## Обработка секретов

- Значения `os.environ/ENV_NAME` сохраняются как `SecretRef{Ref: "ENV_NAME"}`
- Встроенные API-ключи преобразуются в значения `SecretRef`
- В bundle не внедряются открытые секреты

## Ротация ключей

После миграции TokenHub выпускает новые API-ключи. Старые ключи LiteLLM необходимо ротировать. Поле `report.new_keys[]` в отчёте применения (apply report) связывает старые ссылки на ключи с новыми значениями ключей TokenHub.
