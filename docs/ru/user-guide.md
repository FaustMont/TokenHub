# Руководство пользователя по API LLM

Язык: [English](../user-guide.md) | [简体中文](../zh-CN/user-guide.md) | [日本語](../ja/user-guide.md) | Русский

Это руководство предназначено для сотрудников и разработчиков приложений, которые обращаются к утверждённым большим языковым моделям через TokenHub.

## Что потребуется

| Элемент | Назначение |
| --- | --- |
| Base URL | Корневой адрес, совместимый с OpenAI: `http://localhost:8080/v1`; хост Claude Code: `http://localhost:8080` |
| API-ключ проекта | Передаётся как `Authorization: Bearer YOUR_TOKENHUB_API_KEY` |
| ID модели | Возвращается `GET /v1/models` и указывается в поле `model` |
| ID запроса | Используется в Журналах запросов при диагностике сбоев |

Токены входа в консоль не могут вызывать API моделей. Используйте API-ключ проекта из раздела **Управление ключами**.

## Последовательность вызова

1. Откройте **Управление ключами** и создайте или скопируйте API-ключ. Новые ключи отображаются только один раз.
2. TokenHub автоматически привязывает личный ключ к назначенному проекту или к проекту по умолчанию, если проект не назначен.
3. Вызовите `GET /v1/models`, чтобы просмотреть список моделей, доступных для этого ключа.
4. Используйте один ID модели в `POST /v1/chat/completions`, `POST /v1/messages`, `POST /v1/responses` или `POST /v1/embeddings`.
5. Проверьте **Аналитику использования** и **Журналы запросов** по запросам, токенам, затратам и ошибкам.

Страница **Документация API** в консоли остаётся руководством для первоначального знакомства. Для полного интерактивного и машиночитаемого контракта шлюза откройте `http://localhost:8080/docs` в приватном развёртывании или импортируйте `http://localhost:8080/openapi.json` в API-клиент, генератор SDK, инструмент тестирования или корпоративный каталог API. Страница документации хранит введённый ключ проекта только в памяти браузера.

## Просмотр статистики конкретного API-ключа

В разделе **Управление ключами** выберите **Использование** для нужного ключа, чтобы открыть его персональную страницу статистики. На странице отображаются запросы, процент успешных вызовов, задержка, детальные категории токенов, расчётная стоимость для клиента, разбивка по моделям и ошибкам, а также постраничный список деталей запросов. Используйте пресеты за 7, 30 или 90 дней или выберите произвольный диапазон UTC длиной до 366 дней.

Блок квот сравнивает текущие счётчики за день и месяц в UTC с действующими лимитами после объединения политик квот ключа, проекта, команды и глобальных настроек. Статистика принадлежит исключительно выбранному сохранённому ID ключа. Предшественник или преемник при ротации отображается как связанная информация, но никогда не добавляется в итоги. Тела запросов при включённом аудите следуют действующим правилам маскирования и усечения; полный API-ключ никогда не возвращается.

## Тестирование модели в Playground

Откройте **Model Playground** в консоли, чтобы протестировать доступную диалоговую модель без написания скрипта. Каждый ответ показывает режим доставки (потоковый или буферизованный), TTFT при возможности измерения, скорость генерации, общую длительность, входные токены полного контекста, выходные токены, расчётную стоимость, локальное время завершения и ID запроса. Разверните ответ, чтобы увидеть фактические детали. Внутренняя информация о Provider и маршруте отображается только для ролей с разрешением на чтение маршрутизации.

Загрузка изображений доступна только когда в поле `input_modalities` выбранной модели указано `image`; это значение настраивается в каталоге моделей для мультимодальных моделей. Playground принимает изображения JPEG, PNG и WebP с ограничениями: до 4 изображений на сообщение, до 5 МБ на изображение и до 12 МБ изображений за текущую сессию. Экспортированные сессии сохраняют имена файлов, медиатипы и размеры для контекста, но не включают данные изображений.

Сессия временная и существует только на текущей странице, пока не выбран **Экспорт Playground**. **Остановить** сохраняет частичный вывод. **Повтор** создаёт ещё одного кандидата для этого хода и удаляет последующие ходы. Смена модели запускает новую сессию, если явно не выбрано сохранение текущего контекста. Для вышестоящего сервиса, не поддерживающего потоковую передачу, страница использует буферизованный режим и помечает TTFT как неприменимое.

## Список моделей

```bash
curl --request GET \
  --url "http://localhost:8080/v1/models" \
  --header "Authorization: Bearer YOUR_TOKENHUB_API_KEY" \
  --header "Content-Type: application/json"
```

Типичные поля модели:

| Поле | Значение |
| --- | --- |
| `id` | Идентификатор модели в вызовах API |
| `object` | Тип объекта, обычно `model` |
| `created` | Unix-timestamp создания модели |
| `input_token_price_per_m` | Целочисленная цена входных токенов за миллион, совместимая с JieKou |
| `output_token_price_per_m` | Целочисленная цена выходных токенов за миллион, совместимая с JieKou |
| `title` | Заголовок модели |
| `display_name` | Отображаемое имя, совместимое с Anthropic |
| `description` | Описание модели |
| `context_size` | Максимальный размер контекстного окна |
| `created_at` | Timestamp создания в формате RFC 3339, совместимый с Anthropic |
| `max_input_tokens` | Максимальный входной контекст, совместимый с Anthropic |
| `max_tokens` | Настроенный максимум выходных токенов или `0` если не задан |

## Получение информации о модели

```bash
curl --request GET \
  --url "http://localhost:8080/v1/models/gpt-4.1-mini" \
  --header "Authorization: Bearer YOUR_TOKENHUB_API_KEY" \
  --header "Content-Type: application/json"
```

Возвращает один объект модели с теми же полями, что и `GET /v1/models`.

## Chat Completions (Диалоговые завершения)

```bash
curl --request POST \
  --url "http://localhost:8080/v1/chat/completions" \
  --header "Authorization: Bearer YOUR_TOKENHUB_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "gpt-4.1-mini",
    "messages": [
      {"role": "system", "content": "You are an internal enterprise AI assistant."},
      {"role": "user", "content": "Summarize today'\''s support tickets."}
    ],
    "temperature": 0.7,
    "stream": false
  }'
```

Распространённые поля запроса:

| Поле | Обязательное | Примечания |
| --- | --- | --- |
| `model` | Да | Должна быть доступна в `GET /v1/models` |
| `messages` | Да | Список сообщений с ролями `system`, `user` и `assistant` |
| `max_tokens` | Нет | Максимальное количество генерируемых токенов |
| `max_completion_tokens` | Нет | Максимум генерируемых токенов, совместимый с OpenAI; при наличии обоих полей TokenHub использует большее значение |
| `temperature` | Нет | Температура семплирования |
| `reasoning_effort` | Нет | Усилие рассуждения для моделей и маршрутов, поддерживающих это |
| `stream` | Нет | `true` возвращает Server-Sent Events |
| `tools` | Нет | Функциональные инструменты, если поддерживаются вышестоящей моделью |
| `response_format` | Нет | JSON-объект или JSON-схема, если поддерживаются |

### Усилие рассуждения (Reasoning effort)

Chat Completions принимает совместимое с OpenAI поле `reasoning_effort`:

```json
{
  "model": "REASONING_MODEL_ID",
  "messages": [{"role": "user", "content": "Analyze the trade-offs."}],
  "reasoning_effort": "high"
}
```

Responses принимает вложенную форму, совместимую с OpenAI:

```json
{
  "model": "REASONING_MODEL_ID",
  "input": "Analyze the trade-offs.",
  "reasoning": {"effort": "high"}
}
```

TokenHub рассматривает усилие рассуждения как рекомендательную подсказку и не меняет порядок маршрутов. Провайдеры, совместимые с OpenAI, получают значение без изменений. Нативные маршруты Anthropic преобразуют поддерживаемые значения в `output_config.effort`. Нативные маршруты Gemini конвертируют поддерживаемые значения по матрице `thinkingLevel` для Gemini 3 и более поздних моделей или по документированному `thinkingBudget` для Gemini 2.5. Неподдерживаемые или пустые значения опускаются, чтобы действовало поведение вышестоящей модели по умолчанию. Если вышестоящий провайдер возвращает ошибку `400` или `422`, явно указывающую на поле effort, TokenHub повторяет запрос к тому же маршруту один раз без этого поля. Ошибка `400` или `422`, не связанная с effort, возвращается клиенту без повторных попыток у других провайдеров — запрос, считающийся некорректным одним провайдером, некорректен для всех. Каждая физическая повторная попытка учитывается в RPM Ресурса Provider и отображается как попытка маршрута.

Усилие рассуждения для Responses поддерживается на маршрутах OpenAI-совместимых провайдеров, Anthropic и Gemini. Azure OpenAI Responses и потоковые Responses не реализованы; такие запросы возвращают `501 provider_capability_not_supported`.

## Вызов инструментов и мультимодальный контент на маршрутах Anthropic и Gemini

Запросы Chat Completions, маршрутизированные к нативному провайдеру Anthropic или Gemini, транслируют весь запрос и ответ целиком, а не только простой текст.

| Возможность | Anthropic | Gemini |
| --- | --- | --- |
| `tools` и `tool_choice` | Поддерживается | Поддерживается |
| `tool_calls` ассистента и результаты `role: "tool"` | Поддерживается | Поддерживается |
| `parallel_tool_calls: false` | Поддерживается | `501 provider_capability_not_supported` |
| Части изображений | URL `http(s)` и data URI в base64 | Только data URI в base64 |
| Потоковая передача | Инкрементальная ретрансляция | Инкрементальная ретрансляция |

Потоковая передача перенаправляет события вышестоящего сервиса по мере их поступления, поэтому время до первого токена отражает провайдера, а не весь ответ. Типы контента, которые эти маршруты не могут представить (например, аудио-части), возвращают `400 unsupported_content_block` вместо того, чтобы молча исключаться из запроса.

Chat Completions, маршрутизированные к аккаунту Codex Subscription, используют протокол Responses внутренне и предоставляют те же возможности для текста, изображений, функциональных инструментов, параллельных инструментов, продолжения рассуждений и потоковой передачи.

Вышестоящий сервис подписки Codex не принимает поля семплирования на стороне клиента, ограничения выходных токенов или последовательностей остановки. TokenHub принимает эти поля на совместимом эндпоинте, но опускает их в запросе к подписке, поэтому `max_tokens`, `max_completion_tokens`, `temperature`, `top_p` и условия остановки не применяются на маршрутах Codex. Используйте стандартный API Provider, если эти параметры являются договорными.

### Продолжение рассуждений (Reasoning continuation)

Anthropic и Gemini требуют, чтобы непрозрачная подпись, прикреплённая к шагу рассуждения, воспроизводилась дословно на следующем ходе многошагового обмена инструментами. В схеме OpenAI Chat Completions для неё нет отдельного поля, поэтому TokenHub возвращает данные в полях расширения:

| Поле | Данные провайдера |
| --- | --- |
| `message.reasoning_content` | Текст Anthropic `thinking`, части мысли Gemini, итоги рассуждений Codex |
| `message.reasoning_signature` | Anthropic `thinking.signature`, зашифрованные рассуждения Codex |
| `message.reasoning_details` | Зашифрованные рассуждения Codex, привязанные к ID вызова инструмента |
| `message.redacted_reasoning_content` | Anthropic `redacted_thinking.data` |
| `message.tool_calls[].thought_signature` | Gemini `thoughtSignature` |

Воспроизводите эти поля в сообщении ассистента следующего запроса для сохранения непрерывности рассуждений. Для `reasoning_details` сохраняйте полный элемент и его `id`; TokenHub принимает его только когда этот ID соответствует вызову инструмента в том же сообщении ассистента. Клиенты, игнорирующие эти поля, продолжат работать: TokenHub опустит блок рассуждений вместо того, чтобы воспроизводить подпись, которую провайдер отклонит. Подписи помечаются выпустившим их провайдером и никогда не воспроизводятся другому провайдеру.

## Anthropic Messages и Claude Code

TokenHub предоставляет `POST /v1/messages` и `POST /v1/messages/count_tokens` для Claude Code и клиентов, совместимых с Anthropic. Используйте ключ проекта как токен Bearer:

```bash
curl --request POST \
  --url "http://localhost:8080/v1/messages" \
  --header "Authorization: Bearer YOUR_TOKENHUB_API_KEY" \
  --header "anthropic-version: 2023-06-01" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "CLAUDE_COMPATIBLE_MODEL_ID",
    "max_tokens": 2048,
    "messages": [
      {"role": "user", "content": "Understand this repository and summarize its architecture."}
    ]
  }'
```

Нативные маршруты Anthropic сохраняют блоки контента Anthropic и бета-заголовки. Маршруты, совместимые с OpenAI, транслируют текст, изображения, клиентские инструменты, результаты инструментов, параллельные вызовы инструментов и события потоковой передачи. Серверные инструменты Anthropic, которые не могут быть представлены провайдером, совместимым с OpenAI, возвращают `400 unsupported_tool`.

Модели, маршрутизированные к аккаунту OpenAI Codex Subscription, работают через тот же эндпоинт Messages: TokenHub напрямую транслирует Messages в протокол Responses и конвертирует результат обратно в события Anthropic. Claude Code поэтому подключается к TokenHub напрямую; CC-Switch или другой локальный прокси протокола не требуется. Подписи рассуждений Codex передаются через ходы с инструментами, а сессия Claude Code остаётся привязанной к одному работоспособному аккаунту подписки.

На маршрутах Messages через Codex параметры `max_tokens`, `temperature`, `top_p`, `stop_sequences` и форматирование структурированного вывода Anthropic не могут применяться, поскольку вышестоящий сервис подписки не поддерживает эквивалентные поля запроса.

Запросы Claude Code, включающие `mid-conversation-system-2026-04-07`, могут содержать записи `system` внутри `messages`. TokenHub сохраняет эти записи на нативных маршрутах Anthropic и транслирует их в упорядоченные системные сообщения на маршрутах, совместимых с OpenAI. Без этой беты поле `messages` по-прежнему принимает только роли `user` и `assistant`.

Настройте локальный Claude Code с URL хоста TokenHub без суффикса `/v1`:

```bash
export ANTHROPIC_BASE_URL="http://localhost:8080"
export ANTHROPIC_AUTH_TOKEN="YOUR_TOKENHUB_API_KEY"
export ANTHROPIC_MODEL="CLAUDE_COMPATIBLE_MODEL_ID"

claude
```

`ANTHROPIC_AUTH_TOKEN` отправляет ключ TokenHub в `Authorization: Bearer`. `ANTHROPIC_API_KEY` также работает через `x-api-key`, когда заголовок Authorization отсутствует. Подсчёт токенов проверяет доступ к ключу и модели, но не создаёт оплачиваемую запись вывода.

## Фоновые постоянные Responses

Установите `background: true` в `POST /v1/responses`, чтобы сохранить запрос Responses и немедленно вернуть стабильный ID ответа, принадлежащий шлюзу:

```bash
curl http://localhost:8080/v1/responses \
  -H "Authorization: Bearer $TOKENHUB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.4","input":"Summarize the report","background":true}'
```

Прочитайте статус или финальный ответ через `GET /v1/responses/{id}`. Запросите отмену через `POST /v1/responses/{id}/cancel`. Чтение и отмена требуют тех же проекта, API-ключа, владельца атрибуции и текущего доступа к модели, что и исходная отправка; несоответствие возвращает `404`. Сочетание `background: true` и `stream: true` отклоняется, поскольку возобновляемый фоновый SSE не реализован.

Публичные значения статуса: `queued`, `in_progress`, `completed`, `failed` и `cancelled`. Квоты, бюджеты, параллелизм, маршрутизация, политики безопасности, аффинность кэша, учёт затрат, журналы запросов и трассировки применяются воркером до и во время вызова к вышестоящему сервису. Гонка отмены/завершения имеет одного надёжного победителя, тогда как уже понесённые расходы на вышестоящий сервис всё равно учитываются ровно один раз.

Очередь заданий переживает перезапуск сервера. Задание, аренда которого истекла до приёма, безопасно возвращается в очередь. Задание, потерявшее воркера после приёма, помечается как `failed` с кодом `response_execution_lost` вместо повторной отправки, поскольку провайдер мог уже получить его. Реплики PostgreSQL координируют захваты с огороженными арендами и блокировками строк. SQLite поддерживает восстановление после перезапуска, но остаётся развёртыванием с одним бэкендом; не делитесь одним файлом SQLite между репликами бэкенда.

Конверты запросов и результаты зашифрованы в состоянии покоя с помощью `TOKENHUB_SECRET_KEY`; заголовки аутентификации никогда не сохраняются, и сохраняется только ограниченный список разрешённых заголовков протокола. Тела фоновых запросов и ответов не копируются в записи аудита полезных нагрузок в открытом тексте и экспортируемые трассировки, а текст ошибок маршрута вышестоящего сервиса удаляется из их записей попыток маршрута. Сбой шифрования или дешифрования завершается отказом. Финальные полезные нагрузки сохраняются в течение `TOKENHUB_RESPONSE_RESULT_TTL_SECONDS`, после чего шифртексты запроса и результата удаляются, а последующие чтения возвращают `404`. Возвращаемый ID является ID извлечения TokenHub и не транслируется в `previous_response_id` вышестоящего сервиса.

Prometheus предоставляет метрики `tokenhub_gateway_response_jobs_queued`, `tokenhub_gateway_response_job_queue_wait_seconds`, `tokenhub_gateway_response_job_execution_seconds`, `tokenhub_gateway_response_jobs_total` и `tokenhub_gateway_response_job_recoveries_total` при включённых метриках. Параллелизм воркеров, интервал опроса, таймаут, аренда, хранение и ограничения очереди перечислены в [Руководстве по развёртыванию](deployment.md#backend-environment-variables).

## Gemini CLI с GPT через подписку Codex

Gemini CLI может напрямую подключаться к нативному интерфейсу Gemini `v1beta` TokenHub и использовать GPT-модель, маршрутизированную к аккаунту OpenAI Codex Subscription. Установите `GEMINI_API_KEY` в ключ проекта TokenHub, `GOOGLE_GEMINI_BASE_URL` — в хост TokenHub без `/v1beta`, и выберите маршрутизированную GPT-модель. CCswitch не требуется. См. [Использование Codex Subscription GPT из Gemini CLI](gemini-cli-codex-subscription.md) для изолированной и локальной конфигурации проекта, поддерживаемых эндпоинтов, проверки и ограничений.

## Генерация изображений через подписку Codex

`POST /v1/images/generations` принимает совместимые с OpenAI поля `model`, `prompt`, `quality`, `size`, `n` и `response_format`. Используйте публичную виртуальную модель `model: "codex-gpt-image-2"` и `n: 1`. Обычно `gpt-image-2` остаётся отдельной стандартной API-моделью. В качестве узкого исключения совместимости TokenHub сопоставляет запрос на генерацию, помеченный заголовком Codex `originator` или `x-codex-image-turn-id`, с `codex-gpt-image-2` и возвращает `b64_json`; ключ API должен разрешать `codex-gpt-image-2`. Добавьте `Prefer: respond-async` для получения задания на изображение, затем опрашивайте `GET /v1/image-jobs/{id}`.

`POST /v1/images/edits` принимает многочастные эталонные изображения в `image` или `image[]`. `gpt-image-2` пересылает одну `mask` в OpenAI API; редактирование с маской недоступно через аккаунты Codex Subscription. TokenHub отправляет запросы изображений напрямую к эндпоинту Images подписки Codex без установки или запуска Codex CLI, хранит промпты зашифрованными в базе данных, сохраняет входные и выходные изображения на сервере и возвращает подписанные URL для скачивания, действительные 24 часа. Файлы остаются сохранёнными после истечения срока действия URL; повторный опрос задания создаёт новый URL. Выбранный аккаунт Codex должен иметь право на генерацию изображений.

Задания на изображения имеют таймаут выполнения по умолчанию 5 минут, управляемый переменной `TOKENHUB_IMAGE_JOB_TIMEOUT_SECONDS`.

Администраторы настраивают эту возможность в **Каналах провайдеров**: откройте провайдера OpenAI Codex, выберите вкладку **Модели** и установите флажок **Генерация изображений через подписку Codex**. После выбора активного аккаунта TokenHub отображает предупреждение о квоте и отправляет этому реальному аккаунту один запрос `gpt-image-2` низкого качества. Только непустой корректный результат изображения записывает аккаунт как поддерживаемый и создаёт или повторно включает маршрут провайдера. Результат `403` записывает аккаунт как неподдерживаемый; истёкшие учётные данные требуют повторной авторизации; ограничения скорости, таймауты и временные сбои вышестоящего сервиса можно повторить из диалога без перезаписи предыдущего результата проверки возможности. Тест потребляет небольшое количество квоты подписки, и TokenHub никогда не запускает его в фоновом режиме.

Флажок идемпотентно управляет активным маршрутом от `codex-gpt-image-2` к провайдеру OpenAI Codex с вышестоящей моделью `gpt-image-2`. Обновление выполняет однократное заполнение для активных аккаунтов, уже подтверждённых как поддерживаемые. Снятие флажка отключает соответствующие маршруты, но сохраняет результат проверки возможности аккаунта. `codex-gpt-image-2` появляется в `GET /v1/models` только при наличии подходящего маршрута и аккаунта.

## Настройка SDK

```ts
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.TOKENHUB_API_KEY,
  baseURL: "http://localhost:8080/v1",
});
```

## Устранение неполадок

| Код | Вероятная причина | Что делать |
| --- | --- | --- |
| 401 | Отсутствующий, некорректный, отключённый или истёкший API-ключ | Проверьте заголовок `Authorization` и статус ключа |
| 403 | Разрешения проекта, ключа или модели не допускают запрос | Попросите тимлида проверить членство в проекте и доступ к модели |
| 404/503 | Нет включённого работоспособного маршрута для обслуживания модели | Попросите администратора проверить маршруты и состояние провайдера |
| 429 | Достигнут лимит квоты, параллелизма или ресурса провайдера | Подождите сброса или запросите увеличение квоты |
| 500 | Ошибка вышестоящего провайдера или маршрутизации | Найдите `request_id` в Журналах запросов |
